# План разработки игры в жанре Dual Universe

> Рабочее название: **Project DU-like**
> Жанр: MMO-песочница с воксельной стройкой, космосом и игрок-управляемой экономикой.
> Документ — реалистичный план для небольшой команды (3–10 человек), а не клон DU «в лоб» (оригинал делали 100+ человек и $20M+).

---

## 1. Концепция и рамки проекта

### Ключевые столпы (must-have)
1. **Воксельная стройка** — игрок собирает корабли, базы и целые города из вокселей.
2. **Живой мир** — всё построенное игроками сохраняется и существует постоянно.
3. **Космос + планеты** — полёты в атмосфере, выход на орбиту, перелёты между планетами.
4. **Экономика игроков** — добыча → переработка → производство → торговля.
5. **Скриптинг** — Lua-программирование конструкций (двери, турели, автопилот).

### Что СОЗНАТЕЛЬНО урезаем на старте
- Один солнечный система вместо галактики.
- 100–300 игроков на сервер вместо «единого шарда» на тысячи.
- Нет межзвёздных перелётов, политики альянсов и территориальных войн в MVP.
- Упрощённая физика разрушений (без полного воксельного разрушения каждого блока).

> Принцип: **сначала песочница на одном сервере, потом масштабирование**, а не наоборот.

---

## 2. Главные технические вызовы

| Вызов | Суть проблемы | Подход |
|---|---|---|
| Воксельная стройка | Миллионы вокселей на конструкцию, редактирование в реальном времени | Sparse Voxel Octree / voxel hashing, greedy meshing, LOD, RLE-сжатие, дельта-синхронизация |
| Сеть и шардинг | Много игроков в одном мире, интерес-менеджмент | Авторитарный сервер, spatial partitioning, area-of-interest, server meshing по регионам |
| Масштаб космоса | Планеты в сотни км, точность float | Double precision / floating origin, процедурные планеты, LOD-планеты |
| Экономика | Тысячи предметов, заказы, эскроу | Реляционная БД (PostgreSQL), транзакции, event sourcing |
| Lua-скриптинг | Безопасность и производительность | Sandboxed Luau/LuaJIT, лимиты CPU/RAM на конструкцию, event-driven API |
| Персистентность | Всё построенное должно жить вечно | Чанки вокселей в БД/объектном хранилище, версионирование, бэкапы |

## 3. Технологический стек (рекомендация)

### Клиент
- **Unreal Engine 5** — лучший выбор: C++ для воксельного рендера, готовые сеть/UI/физика.
  - Альтернативы: Unity + DOTS (сложнее с большим миром), собственный движок на Rust/Bevy (дольше).
- Собственный плагин вокселей: генерация мешей, LOD, редактирование.
- UI: UMG; карта/рынок — веб-технологии (Coherent/CEF).

### Сервер
- **Rust или Go** для игровых сервисов (высокая нагрузка, безопасность).
- **PostgreSQL** — игроки, инвентари, рынок, метаданные конструкций.
- **Redis** — кэш сессий, очередь событий, presence.
- **NATS/Kafka** — шина событий между сервисами (экономика, чат, логистика).
- Объектное хранилище (S3-совместимое) — сырые воксельные данные, бэкапы.

### Инфраструктура
- Kubernetes + Terraform, мониторинг Prometheus/Grafana, логи Loki.
- Протокол: QUIC + Protobuf/FlatBuffers, дельта-сжатие снапшотов.

## 4. Архитектура (верхний уровень)

```
[Клиент UE5] <--QUIC/Protobuf--> [Gateway]
                                    |
                     [World Server (зона)] -- [Interest Management]
                       |            |
              [Voxel Service]   [Economy Service]
                       |            |
                [PostgreSQL]   [PostgreSQL/Redis]
                       |
                 [Object Storage]
```

- **Авторитарная модель**: клиент только предсказывает, сервер решает.
- **Зоны (cells)**: солнечная система делится на пространственные ячейки; каждая обслуживается своим процессом, при перелёте игрок «переезжает» между серверами (handoff).
- **Interest management**: клиент получает только то, что видит (радиус, окклюзия).
- **Воксели**: конструкция = набор чанков 32³; хранение — палитра + RLE; изменения — дельты.

## 5. MVP — что входит и что нет

### Входит
- 1 планета + орбита + 1 луна.
- Воксельная стройка: размещение/удаление блоков, покраска, сохранение.
- 3–5 типов кораблей-заготовок + свободная сборка.
- Полёт: атмосфера/космос, стыковка, посадка.
- Добыча ресурсов (2–3 вида руды), крафт простых компонентов.
- NPC-рынок + прямой обмен между игроками.
- Lua-скрипты: двери, свет, простой автопилот.
- 50–100 одновременных игроков на одном сервере.
- Аккаунты, сохранение прогресса, чат.

### Не входит (следующие этапы)
- Единый шард на тысячи игроков.
- Полное воксельное разрушение.
- Межзвёздные перелёты, несколько солнечных систем.
- Альянсы, войны, территории.
- Мобильная версия.

## 6. Дорожная карта

### Этап 0 — Пре-продакшн (1–2 месяца)
- [ ] GDD на 10–15 страниц: кор-луп, экономика, прогрессия.
- [ ] Прототип воксельного рендера (1 неделя): куб 64³, редактирование мышью.
- [ ] Прототип полёта корабля в UE5.
- [ ] Выбор движка и серверного стека, настройка репозитория/CI.
- [ ] Оценка бюджета и команды.
- **Выход**: играбельный «серый куб» — летаешь и ставишь блоки.

### Этап 1 — Ядро песочницы (3–4 месяца)
- [ ] Воксельный движок: чанки, LOD, сохранение/загрузка, покраска.
- [ ] Сборка конструкций: сетка, симметрия, копирование, blueprint.
- [ ] Физика конструкций (масса, тяга, коллизии).
- [ ] Полёт и посадка на процедурную планету.
- [ ] Локальный (не сетевой) крафт и инвентарь.
- **Выход**: одиночная песочница — строишь корабль и летаешь.

### Этап 2 — Мультиплеер (4–6 месяцев)
- [ ] Серверный фреймворк: зоны, снапшоты, дельта-синхронизация.
- [ ] Interest management, стриминг вокселей и конструкций.
- [ ] Синхронизация физики кораблей (client-side prediction + reconciliation).
- [ ] Аккаунты, БД, сохранение мира.
- [ ] Чат, группы, базовые права доступа к конструкциям.
- **Выход**: вертикальный срез — 50 игроков строят и летают вместе.

### Этап 3 — Экономика и скриптинг (4–6 месяцев)
- [ ] Добыча руды, переработка, производственные цепочки.
- [ ] Рынок: заказы, эскроу, история цен.
- [ ] Lua-песочница с лимитами и API (сенсоры, двигатели, двери).
- [ ] Торговые терминалы, контейнеры, логистика.
- [ ] Ангар/верфь, ремонт и топливо.
- **Выход**: альфа — игроки сами производят и торгуют.

### Этап 4 — Контент и полировка (3–4 месяца)
- [ ] Процедурные планеты (2–3 биома), атмосфера, погода.
- [ ] Больше блоков, декора, интерьеров.
- [ ] Туториал, новые игроки, античит.
- [ ] Оптимизация: 100–200 игроков на сервер, стабильные 60 FPS.
- [ ] Звук, музыка, UI/UX-полировка.
- **Выход**: бета, закрытое тестирование.

### Этап 5 — Запуск и масштабирование (3–6 месяцев)
- [ ] Server meshing: несколько зон на систему.
- [ ] Нагрузочное тестирование, экономический баланс.
- [ ] Маркетинг, Steam/Epic, серверная инфраструктура.
- [ ] Пост-релизный контент: новые системы, войны, альянсы.
- **Выход**: Early Access.

**Итого до Early Access: ~18–28 месяцев для команды 5–10 человек.**

## 7. Команда и бюджет

### Минимальная команда (5–7 человек)
| Роль | Задачи |
|---|---|
| Геймдизайнер/продюсер | GDD, баланс, планирование |
| C++/UE-программист | Воксели, рендер, физика |
| Геймплей-программист | Сборка, корабли, UI |
| Серверный программист (Rust/Go) | Сеть, зоны, БД |
| 3D-художник/теххудожник | Блоки, корабли, планеты |
| QA/комьюнити (частично) | Тесты, фидбек |

### Оценка бюджета (очень грубо)
- Команда 5–7 человек × 24 месяца: **$600K–$1.5M** (зарплаты/подряд).
- Инфраструктура до альфы: **$500–$2000/мес**.
- Маркетинг Early Access: от **$50K**.
- Solo-разработка: 3–5 лет, бюджет ~$0–50K, но scope MVP придётся урезать ещё сильнее.

## 8. Риски и снижение

| Риск | Вероятность | Снижение |
|---|---|---|
| Scope creep (как у DU) | Высокая | Жёсткий MVP, фича-фриз, «нет» новым идеям до альфы |
| Воксельная производительность | Высокая | Ранний прототип с 1M вокселей, LOD, бюджеты на кадр |
| Сетевой код и читеры | Высокая | Авторитарный сервер с первого дня, античит-план |
| Экономический дисбаланс | Средняя | Симуляции экономики, NPC-слив/приток ресурсов |
| Выгорание команды | Средняя | Вертикальные срезы, плейтесты каждые 4–6 недель |
| «Единый шард» | Высокая | Не обещать в MVP; зоны + handoff как задел |

## 9. Первые 30 дней (конкретно)

**Неделя 1**
- [ ] Утвердить GDD-скелет (1 страница: кор-луп, 3 фичи MVP).
- [ ] Установить UE5, создать проект, настроить Git + LFS + CI.

**Неделя 2**
- [ ] Прототип воксельного чанка 32³: генерация меша, редактирование.
- [ ] Замер производительности: 1M вокселей, цель 60 FPS.

**Неделя 3**
- [ ] Прототип полёта: корабль-куб, физика, камера.
- [ ] Сохранение/загрузка воксельной конструкции в файл.

**Неделя 4**
- [ ] Соединить: летающий корабль из вокселей + посадка на плоскость.
- [ ] Плейтест «серого куба», записать выводы.
- [ ] Решить: продолжаем на UE5 или меняем стек.

---

## 10. Метрики успеха MVP

- 50+ игроков одновременно без десинков.
- Сборка корабля из 100K вокселей за < 30 минут.
- Сохранение/загрузка конструкции < 1 сек.
- Стабильные 60 FPS на среднем ПК.
- Игроки добровольно торгуют друг с другом (рынок живёт без NPC).
- Средняя сессия > 45 минут.

---

## Следующий шаг

Начать с **Этапа 0, неделя 1–2**: прототип воксельного редактора. Это докажет жизнеспособность главной механики раньше, чем будет потрачен хоть один доллар на остальное.
